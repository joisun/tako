# UI source provenance and maintenance

UnderControl prefers official shadcn/ui Base UI components where available. Kibo UI remains the source for specialized Editor and Kanban composites. The registry is configured in `ui/components.json`. Checked-in code is reviewed and built offline; no component registry is contacted at runtime, in CI or during packaging.

Shared Agent identity lives in `components/agents`, with offline DiceBear Micah avatars and stable member IDs. This is application identity presentation, not a second primitive library. Source licenses and attribution for AI Elements, DiceBear/Micah and PDF extraction are also retained in `server/vendor/THIRD_PARTY_NOTICES.md` and its accompanying license files.

The shadcn CLI was attempted for docs and registry inspection; its Node HTTPS requests failed in this environment. Exact official registry JSON was retrieved through HTTPS and reviewed instead. SHA256 of retrieved source JSON is recorded in the job audit. No existing components were blindly overwritten by a preset. The unused top-level `kibo-ui` npm package is not installed.

## Maintenance rules

- `components/ui` owns shared primitives; `components/kibo-ui` owns approved Kibo composites. Business components remain under features. Do not add a second primitive library.
- Reuse `lib/cn.ts`, `lib/motion.ts` and `styles/tokens.css`. Colors and durations belong to tokens, not a second palette.
- Before adding a registry item, inspect transitive dependencies, aliases and all exported code. Only install the dependencies its actual retained exports use; record source, date, license and adaptations.
- Keep accessible names, keyboard control, focus restoration, disabled/pending behavior and reduced-motion support. Keep offline single-file builds network independent.
- Historical dotUI-derived application CSS remains under its original MIT notice; the React Aria source components and bridge are replaced. Historical specs describe the earlier implementation, not current guidance.

License text is included in [UI notices](../../../THIRD_PARTY_NOTICES.md).

## AI Elements migration

The former AI Elements site announces deprecation at the end of November 2026. Current [shadcn AI Elements](https://ui.shadcn.com/docs/ai-elements) are source compositions, not a new execution SDK. Use the Base UI variants for future AI presentation updates. Tool, Task and ChainOfThought now render through the shared Trace primitive. The Reasoning helper remains available as a Trace composition; Teams no longer uses a permanent reasoning disclosure in the conversation. It shows only a transient live public reasoning summary while the current part streams. Teams Message/Bubble and Message Scroller now use native shadcn source; PromptInput retains its call-site exports while composing Input Group around the Tiptap custom control. Teams Markdown selects the native Code Block; Sessions/Schedule Markdown keeps its existing renderer. Definition/attachment wrappers still retain their business-specific adaptation. Keep the current per-part timeline, public reasoning section boundaries, Tiptap Mention, source attribution and runtime contracts. Kibo remains the source for Editor and Kanban. Do not replace all components or add a parallel primitive runtime to migrate one pattern.

Teams renders ordinary activity as flat rows, preserving each recorded event ID and timestamp; no outer command-count disclosure is added. Teams shows one transient live summary per currently thinking member using official shadcn pure CSS shimmer. It uses the first non-empty public reasoning line, updates with streamed text, and shows a neutral pending label only before summary text exists. It removes the indicator when thinking finishes or a tool/reply begins; completed reasoning summaries, history controls and empty author rows are not kept in the conversation. Recorded public parts remain intact. Tool input/output opens on request; manual expansion survives completion. Token usage is a focusable Popover, cancellation uses a readable neutral label, and user messages do not repeat a name/avatar. Reduced motion disables shimmer. Native hook continuations are retained in a separate collapsed ChainOfThought; they do not acquire inferred recipients. Keep activity containers mounted when a reasoning-only section gains its first tool. Each rendered message group registers its stable messageId with MessageScrollerItem.


## Native chat source (2026-11-03)

Message, Message Scroller, Input Group, Bubble and Code Block come from the official `base-nova` registry under MIT. Message/Scroller retain upstream structure; Input Group/Bubble/Code Block retain used exports and reuse existing Button, cn and Lucide. Code Block uses plain text already supplied by Markdown, with no remote highlighting resources. `@shadcn/react` 0.3.1 supplies the official scroller engine; existing `use-stick-to-bottom` is still used by Schedule and was not removed. The shimmer utility is the MIT `shadcn` 4.22.0 CSS source, locally retained without bundling the CLI or a second animation implementation. Provenance hashes and checks are in the Agent Loop job log. No registry is contacted by the built UI.

Before a Run emits its first native content, Teams renders a separate ephemeral presence row from its durable queued/starting/running status and native Session ID. It must not wait for a reasoning token to acknowledge accepted work, fabricate thinking, or persist a placeholder message. Native output replaces that row; usage-only metadata does not.
