# TAKO 品牌基础

状态：用户已确认采用 TAKO。本文件记录 0.19.0 已落地的品牌约定，图形资源后续设计。

依据：用户提供的 tako_brand_kit 中的 BRAND_GUIDE.md、README-HERO-DRAFT.md、MASCOT-BRIEF.md、RENAME-CHECKLIST.md 和 brand-tokens.json，以及当前项目的 README、设计变量与迁移机制。未采用该素材包的 SVG 图形。

## 品牌定位

TAKO 是面向开发者的本地优先 Agent 工作台，统一管理会话、自动化任务和多 Agent 团队。

| 项目 | 约定 |
| --- | --- |
| 展示名 | TAKO |
| 机器标识 | tako |
| 品牌副标题 | Your AI Agent Crew |
| 品牌标语 | One Brain. Many Agents. |
| 中文产品说明 | 让你的 Agent 团队有序协作。 |
| 语气 | 直接、具体、可靠，带少量亲和力 |

统一使用 Your AI Agent Crew，避免同一位置混用 The Agent Crew、Your AI Agent Crew 和不同的产品定义。产品介绍先说明实际功能，品牌标语承担记忆点。

One Brain 表达人的目标与共同上下文，不作为单模型、单一中心 Agent 或固定协作架构的技术承诺。章鱼的八只腕也不对应成员数量、模块数量或并发上限。

Local-first 表达本机管理会话记录、配置、运行事实与工作资料。不要写成“所有功能离线运行”或“从不访问外部服务”：模型调用取决于 Runtime 配置，Agent 池会读取外部目录。应说明复用用户已配置的客户端和模型服务。

## 文案与模块名称

对外首次介绍模块时可以使用 TAKO Sessions、TAKO Actions、TAKO Teams。在应用内部，品牌区显示 TAKO，导航仍显示 Sessions、Actions、Teams，避免每个入口重复品牌名。

| 现有能力 | 对外描述 |
| --- | --- |
| Sessions | 浏览、查找和继续原生 Agent 会话 |
| Actions | 用 Markdown 定义工作，通过定时、手动或 HTTP 请求执行 |
| Teams | 按职责组建专业 Agent 团队，分派工作、交换结果并验证交付 |
| Agent 管理与市场 | 发现、安装和更新角色定义；引导式组队主动检索专业角色 |
| Runtime 适配 | 连接已有编码客户端，不把角色定义当成执行环境 |

Agent 市场已实现，不能照搬素材包中“Market 是可选未来能力”的描述。Runtime 与市场也不因此新增顶层导航。

能力文案沿用现有兼容边界，不笼统宣称所有 Runtime 都支持相同的会话浏览、写入或执行功能。不将排队、投递成功或 CLI 退出成功写成任务已完成。

README 首屏文案建议：

> TAKO — Your AI Agent Crew
>
> One Brain. Many Agents.
>
> A local-first workspace to manage agent sessions, automate actions, and coordinate professional agent teams.

中文介绍建议：

README 使用真实版本、GPL-2.0-only 许可证和已验证的安装方式，删除来源草稿中的 REPLACE 徽章、占位安装指令及“未来会提供”说明。

## 视觉方向

产品界面延续已有的中性深色、紧凑排版与 Geist 字体。品牌更名不扩大为导航或页面布局重建。紫色用于品牌识别和少量关键交互，插图与营销物料承担更活泼的表达。

品牌色与界面语义色分开：

| 用途 | 建议值 | 使用规则 |
| --- | --- | --- |
| 品牌主色 | #6D4AFF | 关键按钮、标志与少量强调 |
| 深色界面上的品牌文字 | #B8A5FF | 链接、轻量品牌提示；不覆盖正文色 |
| 产品底色 | #0A0A0A / #101010 / #1A1A1A | 继续使用现有语义变量 |
| 正文 | #EDEDED | 继续使用现有 text-primary |
| 亮色品牌物料 | #F3F0FF / #201B35 | 用于对外物料，不代表新增产品亮色模式 |
| 辅助点缀 | #67C7F5 / #FFB65C | 主要留给后续插画，避免多色控制台 |

按 sRGB 相对亮度计算：白字配 #6D4AFF 为 5.15:1；#6D4AFF 配 #0A0A0A 为 3.84:1；#B8A5FF 配 #0A0A0A 为 9.30:1。普通小字不直接用主紫色放在当前深色背景上。实际控件还要结合字号、状态和焦点验证，不能用色值计算替代界面验收。

成功、警告、错误继续使用现有语义色，不全部改成紫色。等待、运行、失败、完成继续同时保留可读状态文字。

## Logo 与后续图形

用户已选择第一方向：圆润章鱼印记。当前 PNG 资源包含透明独立标志、应用图标、浅色背景横版和深色背景单色横版，见 [Logo 资源与使用说明](../../assets/brand/tako/README.md)。浏览器已检查 16、24、32、48px 及深浅色背景，原始方向与渲染校样一并保留。

当前标志采用六个可见腕端的简化剪影，表达章鱼形象；不把可见腕端数量解释为 Agent 数量或并发承诺。Logo 使用简洁双眼，吉祥物的姿态和表情仍需另行设计。

本轮未采用来源素材包 SVG，也没有将旧刺刺图形冒充新品牌。交付为 PNG，尚无可编辑矢量母版。后续补充 SVG 时应沿用已选轮廓，单独核对曲线、纯色与小尺寸效果。

## 更名落地范围

以下为准备范围，不表示远端或本机已经切换：

| 层次 | 后续处理 |
| --- | --- |
| 产品界面与文档 | 更新展示名、页面标题、品牌文案、模块说明与资源引用 |
| 代码与插件 | 按最终名称更新 CLI、包元数据、插件、MCP、环境变量和发布文件 |
| GitHub | 确认最终仓库地址与目标是否可用后处理，保留历史提交和 Release 资产 |
| 本机安装 | 复用现有迁移事务，核对目录冲突和真实执行状态，保留回滚入口 |
| 持久化标识 | 新写入使用新名称；按实际旧格式提供读入兼容，不替换历史正文 |

Action ID、secret、Markdown 正文、定时配置、执行历史、输入、Session 关联和用户业务目录不因品牌变化重建。端口不因更名改动，继续使用现有管理、HTTP Trigger 与 43130 开发入口。

不得把当前源代码中的 undercontrol、历史 rillo 标识、旧 Release 文件或原生 transcript 统一做全局替换。先区分现行品牌、协议兼容与历史事实。旧格式读取仅保留在明确的迁移或兼容位置。

品牌名确认后，先完成代码与迁移清单，再执行外部仓库及本机安装切换；静态资源按本次要求另行设计。
